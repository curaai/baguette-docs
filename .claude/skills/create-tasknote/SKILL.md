# TaskNote 작성
태스크의 경로·속성·본문·재개 정보 형식은 vault 루트의 `TaskNotes/README.md`를 따른다.
관련 문서는 `.claude/README.md`와 폴더 목차에서 찾는다.

## 작성 절차
1. 요청의 제목·대상 기획·context를 확인한다. 같은 작업의 태스크가 있으면 읽고 중복 생성 대신 갱신 초안을 만든다.
2. context는 명시된 값이나 관련 태스크에서 확인한다. 근거가 없거나 여러 후보면 구조화된 질문 도구로 묻는다.
3. 기획을 작업으로 나눌 때는 승인된 체험·기능에 근거해 목표·작업·완료 기준을 정리한다. 필요할 때 범위 밖을 둔다.
4. 구현 여부를 확인해야 하면 관련 코드와 에셋만 확인한다. 확인하지 못한 사실은 미확인으로 두고, 현재 구현 스냅샷이나 코드 구조를 본문에 저장하지 않는다.
5. 저장 경로·속성·본문을 채팅에서 한 번에 보여 주고, 구조화된 질문 도구로 저장 승인을 받는다.
6. 승인된 초안만 저장하고 경로를 알린다. 이미 같은 초안의 저장 승인을 받았으면 다시 묻지 않는다.

## 주의
- 기획의 핵심 방향이 미정이면 작업으로 확정하지 않는다. 미결을 짚고 그 결정에 의존하는 분해를 기다린다.
- 태스크 하나로 끝나지 않을 때는 분리할 후보와 이유를 먼저 보여 준다. 요청 범위를 넘어 여러 태스크를 자동 생성하지 않는다.
- 기획서 수정이나 새 `specs/` 문서 생성을 대신 수행하지 않는다.
- 태스크 본문에 다른 문서 링크를 넣지 않는다. 필요한 연결은 TaskNotes 목차 표에 둔다.
- 기존 노트를 갱신할 때 상태·우선순위·관계 속성과 기존 속성 형식을 보존한다. 변경 요청이 있을 때만 바꾼다.
