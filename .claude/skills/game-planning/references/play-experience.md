# 플레이 경험 검토
플레이어의 행동이 의도한 경험으로 이어지는지 살핀다.
관련 항목만 사용한다. 검토 목록을 기획서의 새 장으로 붙이지 않는다.

## 행동과 반응
- 플레이어가 실제로 할 수 있는 행동과 그 행동을 고르는 이유를 찾는다.
- 규칙의 설명과 실제로 유리해지는 행동이 맞는지 살핀다. 한 행동만 반복하는 편이 항상 유리하면 다른 선택의 의미를 검토한다.
- 입력이 받아들여졌는지, 성공·실패가 무엇인지 플레이어가 알 수 있는지 확인한다. 의도한 지연·모호함은 일반적인 피드백 부족과 구분한다.
- 실패 뒤 다시 시도하거나 다른 행동을 고를 여지가 있는지 살핀다. 모든 실패를 벌점이나 막다른 길로 만들지 않는다.
- 소리·움직임·화면 반응은 느끼게 할 효과로 설명한다. 흔들림·보상·화려한 효과를 기본 해법으로 추가하지 않는다.

## 반복과 부담
- 반복할 때 달라지는 관찰·판단·결과가 있는지 살핀다.
- 새로운 규칙을 더하기 전에 기존 행동을 깊게 만드는 방법을 검토한다.
- 보상·성장·자원 경제는 해당 기획에 있을 때만 검토한다. 공포나 서사 게임에 영구 성장·재화를 의무화하지 않는다.
- 조용한 구간이 관찰·예상·휴식에 기여하는지 살핀다. 의도한 정적을 할 일 없는 시간으로 단정하지 않는다.

## 작은 검증
가장 불확실하고 영향이 큰 가정을 한 가지 고른다.
가정을 확인할 짧은 플레이 장면과 관찰할 행동을 제안한다.
테스트에서는 설명을 들어야만 진행하는 지점, 반복·망설임·이탈을 관찰한다. 수행하지 않은 테스트는 계획으로만 적는다.
프로젝트의 Visual Blockout 방향을 존중한다. 검증을 이유로 씬 제작이나 다른 구현 작업을 자동 시작하지 않는다.
수정안은 요청 범위에 맞춰 제안한다. 기능 제거·새 메커닉·일정 변경을 대신 확정하지 않는다.
