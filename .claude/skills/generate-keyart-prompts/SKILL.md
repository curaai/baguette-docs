# 키아트 프롬프트 생성 (채팅 출력)

키아트·배경 장면 전용 래퍼다. 범용 에셋 원화 파일 모음은 `generate-asset-prompts`에 맡기고, 여기서는 **실내외 배경 장면**을 Nano Banana에 붙여넣을 영문 프롬프트로 **채팅에** 낸다. 파일을 `assets/`에 쓰지 않는다.

**왜 장면 배경을 따로 두는가:** 장면 배경은 에셋 하나의 모양보다 **공간 가독성·시점·조명·깊이**가 실패 지점이다. 실외는 원경 레이어, 실내는 방의 닫힌 구조와 시선 흐름을 우선 고정한다.

## 하지 않는 것

- `assets/**` 또는 `원화_테스트/`에 프롬프트·이미지 파일을 **Write하지 않는다** (채팅 붙여넣기만).
- ComfyUI positive/negative·노드 안내를 **기본으로 만들지 않는다** (PD가 명시적으로 Comfy를 요청하면 한 줄로 `generate-asset-prompts`로 넘기라고만 한다).
- 캐릭터 표정·프롭·FX·UI 요청이면 이 스킬을 쓰지 않고 `generate-asset-prompts`로 안내한다.
- 레퍼런스 이미지가 있으면 **반드시 `Read`로 연다**. 이미지에서 시점·레이아웃·스타일 중 사용자가 참고하라고 한 요소를 구분한다. 문서와 다른 요소를 조용히 섞지 않는다. 이미지가 없으면 문서 근거만으로 진행하되, 채팅에 “레퍼런스 없음”을 한 줄 밝힌다.
- 문서 충돌·미결을 조용히 고르지 않는다 — 프롬프트 위에 `⚠️ 미결`로 남긴다.
- 범위가 비어 있으면 추정으로 쓰지 않는다 — 아래 §0 게이트를 탄다.

## 범용 스킬과의 관계

| 요청 | 담당 |
|------|------|
| 키아트·마케팅 장면·실내외 배경 장면 프롬프트 | **이 스킬** |
| 캐릭터·프롭·UI·일반 원화 + `assets/{이름} 프롬프트/` 파일 | `generate-asset-prompts` |
| ComfyUI 키워드 변환·파일 저장 | `generate-asset-prompts` (이 스킬에서 대행하지 않음) |

프롬프트 **문단 골격**(공간 → 구도 → 조명 → 스타일 → 기술조건)은 범용 스킬과 같은 질서를 따르되, 실외는 **레이어·시점**, 실내는 **방의 구조·시선 흐름·광원 방향**을 필수에 올린다. 공통 골격은 [template.md](template.md), 실내 세부 규칙은 [indoor-background.md](indoor-background.md)를 따른다.

## 워크플로

### 0. PD 입력 게이트

사용자 메시지에서 아래를 파싱한다. **기본값이 지정된 항목은 그 기본값을 적용**하고, 그 밖에 비어 있거나 애매한 항목만 `AskUserQuestion`을 **한 번씩** 호출한다. 텍스트만 “어때요?”는 금지. `AskUserQuestion` 도구가 없으면 옵션 라벨을 짧게 나열해 PD가 고르게 한다. **확정 전 프롬프트 본문 출력 금지.**

| 순서 | 항목 | 있으면 | 없으면 |
|------|------|--------|--------|
| 1 | **장면 종류·시점·구도** | 그대로 | 실외: 원경만(능선·하늘) / 절터에서 본 원경(담장 힌트+능선) / 산길·일주문에서 본 원경. 실내 기본: 메인 배경 설정 보드(높은 3/4 컷어웨이) + 서브 단일 실내 배경(입구 안쪽에서 공간의 초점을 보는 시점). 다른 구도를 원하면 Other |
| 2 | **개수·시리즈** | 숫자·시리즈 그대로 | 실내 기본 2장(메인 보드 1장 + 서브 단일 배경 1장). 실외: 단일 1장 / 시점만 2~3안 / **시간대 시리즈(낮·폭우밤·새벽)**. 사용자가 장수나 시리즈를 지정하면 그 요청 우선 |
| 3 | **색감·테마·무드** | PD 문구 그대로 | art-direction·관련 narrative에서 뽑은 3~4옵션 + Other. **추론으로 채우지 말 것** |
| 4 | **조명 연출** | 시간대·광원 지정 시 버전별 문단에 반영 | 단일 장면에 조명 문단 **포함** / **생략**(색감·무드만) / **시간대 시리즈로 교체** |

게이트가 끝나면 채팅에 **확정 범위 4줄 요약** 후 §1로 간다.

### 1. 근거 수집 (순서 고정)

1. `foundation/art-direction.md` — **실사에 가까운** 톤·고지 고립·팔레트 원칙. 레퍼런스는 사용자가 지정한 참고 요소(구도·스타일 등)를 반영하고, 공간 설정은 장면 문서를 따른다.
2. 장면 문서 (요청에 맞게 선택)
   - 절 주변·레이어 정본: `narrative/opening-mountain-landscape.md`
   - 산길·일주문: `narrative/environment/approach-entrance.md`
   - 절터·외관: `narrative/environment/temple-exterior.md` 및 관련 `(temp)-*` (있을 때만)
   - 실내 공통: `narrative/environment/(temp)-temple-interior.md`
   - 실내 건물별: `narrative/environment/(temp)-temple-building-{daeungjeon|yosachae|myeongbujeon|utility}.md` 중 요청 공간에 맞는 문서
3. 레퍼런스 이미지 — `assets/`, `reference/`, 원화 폴더에 있으면 `Read`로 1~3장. **없으면 스킵 + 채팅에 명시**
4. 관련 `Tasks/*.md`는 참고만 (자동 수정 금지)

경로 `planning/direction/` 등은 이 레포에 없으면 찾지 말고 위 목록을 쓴다.

### 2. 실외 배경 레이어 규칙 (프롬프트에 반드시 반영)

문서의 근·중·원을 **탐험 맵이 아니라 화면 깊이**로 번역한다.

| 레이어 | 프롬프트에 넣을 것 | 넣지 말 것 |
|--------|-------------------|------------|
| **근경** | 시점별 최소 힌트만 (절터: 담장·석축 실루엣; 산길: 길·표식 일부; 원경만: 거의 비움) | 플레이어가 걸어 들어갈 듯한 디테일 과다 |
| **중경** | 사면·수관 군집, 안개 속 줄기 — 밀도는 “채우기”가 아니라 깊이 | 하늘 전체를 덮는 수관 |
| **원경** | 능선 **2~3겹**(산길은 1~2겹), 저밀도 수관 실루엣, 건물보다 **명도 한 단계 낮음** | 원경을 탐험 공간·관광 포스터 디테일로 그리기 |
| **하늘** | 절터 시점에서는 **주 개방면** | 밤·폭우에서만 하늘이 막힌 숲 천장처럼 읽히게 하기(그 톤이 목표면 제외) |

공통 배제(영문 negative 감각으로 본문에 명시): characters walking the path as heroes, tourist brochure temple, readable signage/text, watermark, hyper-detailed explorable foreground filling the frame.

**실내 배경이면 위 표의 산·하늘 레이어를 적용하지 않는다.** 대신 [indoor-background.md](indoor-background.md)의 닫힌 공간, 입구에서 초점까지의 시선 흐름, 실내 광원 규칙을 적용한다.

### 3. 시점·시간대

**시점**은 §0에서 고른 그대로 장면 문단에 쓴다. 실내는 장수 미지정 시 [indoor-background.md](indoor-background.md)의 기본 두 구도(메인 배경 설정 보드 + 서브 단일 실내 배경)를 각각 별도 이미지용 프롬프트로 출력한다. 두 장을 한 이미지의 분할 패널로 합치지 않는다. 사용자가 장수나 구도를 지정하면 해당 요청을 우선한다.

**시간대 시리즈**를 고르면 한 응답에 **공통 베이스 + 버전별 교체 문단**으로 낸다 (파일로 쪼개지 않음).

| 버전 | 레이어·분위기 힌트 (문서 정합) |
|------|-------------------------------|
| **낮** | 산 중턱 햇빛, 큰 나무 그림자로 일부 건물만 그늘; 능선·숲 가독 |
| **폭우·밤** | 능선·아래 숲을 안개·어둠 실루엣으로 감춤; 국소광(손전등·절 불빛)만 공간 일부 |
| **새벽** | 안개·청록을 줄이고 중성광; 능선 윤곽이 드러나며 잔향만 남김 |

단일 장이면 조명 문단은 §0 선택에 따른다.

### 4. Nano Banana 프롬프트 골격

출력은 채팅 마크다운만. [template.md](template.md) 순서를 따르며, 실내 기본 두 장은 `프롬프트 1 — 메인: 배경 설정 보드`, `프롬프트 2 — 서브: 단일 실내 배경`으로 구분한다. 각 블록은 서로 별도로 생성하는 이미지 한 장을 설명한다.

1. `[컨셉]` 한 줄 + 근거 경로 + (있으면) `⚠️ 미결` + (있으면) 참조 이미지 경로
2. **공간 고정** — 실외는 근/중/원/하늘 레이어, 실내는 방의 구조·시선 축·광원 방향을 문장으로 고정
3. **장면/구도** — 카메라·시점 + **색감·테마·무드**(영문, 필수)
4. **조명 연출** — §0에서 포함/시리즈일 때만
5. **스타일 앵커** — 실외는 늦여름 장마철 한국 산중 사찰, 실내는 요청한 건물과 해당 실내 문서의 분위기. 공통으로 **실사에 가까운(near-photoreal / grounded photographic)** 톤을 쓰며, 레퍼런스 스타일을 따라 하라는 명시 요청이 있으면 그 요청을 반영한다.
6. **기술 조건** — 해상도·비율(미지정 시 **FHD 1920×1080, 16:9**), no text/watermark, 인물 없음(요청 시에만 예외)

**자가검수:** 색감·테마·무드가 영문으로 최소 1문장; 실외면 레이어 4항과 원경 규칙, 실내면 방의 닫힌 구조·시선 축·광원 방향이 빠지지 않았는지 확인한다. 실내에 하늘이나 산 레이어를 강제로 넣지 않는다.

### 5. 채팅 출력 형식

```markdown
## 확정 범위
- 시점: …
- 시리즈/개수: …
- 색감·무드: …
- 조명: …

## 사용법 (Nano Banana)
1. (참조 이미지가 있으면) 해당 파일을 함께 업로드
2. 아래 `프롬프트` 영문을 그대로 붙여넣기
3. 같은 채팅에서 레이어·명도만 수정 지시

## 컨셉: {이름}
근거: …
⚠️ 미결: …   ← 있을 때만
참조 이미지: … ← 있을 때만

### 프롬프트
…
```

시간대 시리즈면 `### 프롬프트` 안에 공통 베이스 + `--- 낮 ---` / `--- 폭우밤 ---` / `--- 새벽 ---` 교체 문단.

마지막에 **우선 추천 1개**(또는 시리즈 중 먼저 돌릴 버전)만 짧게 짚는다. Comfy·파일 저장 권유는 하지 않는다.

## 예시

**PD**: "배경 원경 키아트 프롬프트 Nano로"
→ §0: 시점·개수/시리즈·색감·조명. 확정 후 채팅에 레이어 고정 영문 프롬프트.

**PD**: "절터에서 본 원경, 낮·폭우밤·새벽 시리즈"
→ 시점·시리즈 있음. 색감·조명(시리즈면 조명=교체)만 게이트 → 공통+3버전 채팅 출력.

**PD**: "대웅전 내부 배경 원화, 입구에서 불단이 보이는 3/4 시점"
→ 대웅전 실내 문서와 실내 공통 문서를 확인하고, 문턱·마루·불단의 시선 축과 실내 광원으로 프롬프트를 구성한다. 실외 산·하늘 레이어는 넣지 않는다.

**PD**: "몬스터 프롭 원화 파일로"
→ 이 스킬 대상 아님 → `generate-asset-prompts`로 안내.
