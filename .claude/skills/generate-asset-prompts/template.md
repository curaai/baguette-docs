# 이미지 프롬프트 구성 예시

요청한 결과에 맞는 예시만 사용한다. 중괄호 안내와 불필요한 항목은 실제 출력에서 제거한다. 제목·근거·사용 안내는 프롬프트 본문과 분리한다.

## 신규 디자인·단일 프롬프트

```text
프롬프트:
{대상과 용도, 요청한 형태·재질·표현}
{필요한 시점·구도·개체 수·배경 처리}
{요청 또는 승인된 근거에서 정한 스타일·색·조명 중 필요한 조건}
{비율·해상도 등 지정한 제작 조건과 필요한 배제 조건}
```

레퍼런스가 없으면 참조 이미지 항목을 만들지 않는다. 플랫폼 공통 초안에는 도구 전용 구문을 넣지 않는다.

## 기존 이미지의 부분 수정

```text
참조 이미지: {확인한 이미지 이름 또는 경로, 사용할 역할}

프롬프트:
{대상 이미지에서 유지할 정체성·디자인·배치 등}
{바꿀 부분과 원하는 결과}
{변경 범위에 필요한 제작 조건}
```

실제 프롬프트에는 유지·변경 범위를 생성 도구가 이해할 문장으로 쓴다. 예를 들어 신발 색만 바꾸는 요청에 몸 전체를 `exactly as-is`로 고정해 변경 지시와 충돌시키지 않는다.

## 변형·여러 뷰

```text
프롬프트 1 — {버전 또는 뷰 이름}:
{공통 정체성과 제작 조건을 포함한 완성 프롬프트}

프롬프트 2 — {버전 또는 뷰 이름}:
{같은 고정 조건과 이번 버전의 변경 조건을 포함한 완성 프롬프트}
```

한 장 안의 다중 뷰를 요청했다면 별도 이미지용 프롬프트로 나누지 않는다. 한 프롬프트에 뷰의 개수·순서·각도·간격·크기를 설명한다. 시리즈의 공통 베이스와 교체 문장만 원하는 요청에는 조합 방법을 함께 설명한다.

## ComfyUI 등 워크플로에 맞춘 출력

```text
대상: {알고 있는 모델·워크플로}
미확인 조건: {실행에 영향을 주는 미확인 사항이 있을 때만}

Positive / 주 프롬프트:
{확인한 모델·인코더에 맞는 자연어 또는 태그 표현}

Negative:
{지원하는 워크플로에서 필요한 배제 조건이 있을 때만}
```

Negative를 사용하지 않으면 제목도 생략한다. ComfyUI 단독 결과는 다른 플랫폼의 파일 없이 사용할 수 있게 작성한다. 이미지 참조가 필요하면 실제 워크플로에서 사용할 입력과 역할을 본문 밖에 안내한다.

## 파일 전달

단일 파일은 위의 해당 형식을 사용한다. 여러 파일이면 사용자가 원하는 분할 단위로 나누고 실제 파일 이름을 안내한다. 파일 수와 생성 이미지 수를 혼동하지 않는다.

별도 사용 안내가 필요할 때만 다음 정보를 적는다.

```text
{프롬프트 묶음 이름} — {요청한 플랫폼 또는 범용}

사용법: {붙여넣을 블록, 필요한 입력 이미지, 별도로 설정할 값}
파일 목록: {실제로 만든 파일과 각 용도}
참조 자료: {실제로 사용하는 이미지와 참고 역할, 있을 때만}
```

모델 버전·결과 저장 위치·참조 경로를 임의로 고정하지 않는다. 프로젝트의 문서 링크는 README 목차에서 관리한다.
