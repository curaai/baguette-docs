# 문서 정리
필요한 내용을 기존 문서와 목차에서 찾기 쉽게 정리한다.
공통 규칙과 문서별 담당은 유지한다. 새 기록 저장소나 자동 정리 기능을 만들지 않는다.

## 확인
1. 요청한 문서·폴더 범위를 정하고 해당 README와 관련 문서만 읽는다.
2. 중복, 찾기 어려운 내용, 서로 다른 주장과 오래된 초안을 구분한다.
3. 사용자 승인과 문서의 역할을 확인한다. 날짜·분량·완성도만으로 어느 내용이 정본인지 판단하지 않는다.
4. 남길 고유 내용과 옮길 위치를 먼저 정리한다. 게임 내용의 충돌은 양쪽 근거를 보여 주고 사용자가 결정하게 한다.

## 정리 원칙
- 새 문서는 기존 문서에 자연스럽게 담기 어려운 독립 주제일 때 만든다. 대화나 작은 메모를 자동으로 문서화하지 않는다.
- 하나의 주제를 길이만 보고 나누지 않는다. 서로 다른 목적이 섞였을 때 분리를 검토한다.
- 문서를 합칠 때 고유한 결정·이유·미결 사항을 누락하지 않는다. 기존 내용을 없애거나 보관 위치를 바꾸는 안은 변경 범위에 명시한다.
- 사용자가 이미 정한 통합·분리·이동은 그 범위에서 수행한다. 새 구조나 내용 선택이 필요할 때만 공통 질문 규칙을 따른다.
- 목차와 링크는 공통 작업 규칙을 따른다. 새로 만들거나 이동한 문서는 해당 README 표와 연결된 경로를 갱신한다.
- 진행 중 태스크의 상태·우선순위·관계 속성을 문서 정리만으로 바꾸지 않는다. 재개 정보는 TaskNotes 안내가 관리한다.

## 결과 확인
원래 있던 고유 내용이 보존됐는지와 옮긴 문서의 경로를 확인한다.
기준이 확정되지 않은 충돌은 미결로 남긴다. 임의로 한쪽을 삭제해 해결하지 않는다.
검토만 요청받았으면 채팅에 발견 사항과 정리안을 보고한다.
수정 요청을 마쳤으면 바꾼 문서, 이유, 남은 미결을 짧게 알린다. 별도 정리 로그를 자동으로 만들지 않는다.
