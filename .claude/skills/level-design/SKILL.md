# 공간 플레이 설계
플레이어가 공간에서 무엇을 보고 어디로 움직이는지 설계한다.
게임 디자이너가 담당한다. 미술 방향은 아트 담당, 사건의 의미는 서사 담당과 맞춘다.

## 시작
대상 구역, 플레이어의 목표, 이미 승인된 방향을 확인한다.
새 방향 선택이 필요하면 공통 작업 규칙을 따른다. 승인된 동선의 후속 수정에 킥오프를 반복하지 않는다.
필요한 장면 문서와 기획만 목차에서 찾는다. 기존 공간 설정을 임의로 바꾸지 않는다.

## 설계
1. 구역에 들어오는 순간, 목표에 이르는 길, 나가는 순간을 정한다.
2. 주요 갈림길마다 보이는 것과 가려지는 것을 살핀다. 출입구·특징물·소리·빛이 어떤 행동을 유도하는지 정한다.
3. 필수 동선과 선택 탐색을 구분한다. 돌아오거나 단서를 놓쳤을 때 이어갈 길도 살핀다.
4. 긴장·발견·휴식이 공간과 이동 시간에 따라 어떻게 바뀌는지 정한다. 모든 방을 같은 강도로 채우지 않는다.
5. 플레이어 시점과 행동 범위에 맞는 통로·시야를 검토한다. 정해지지 않은 치수나 이동 능력은 추정하지 않는다.
6. 확인할 장면을 좁혀 테스트 방법을 제안한다. 실제 관찰 결과와 예상은 구분한다.

## 공포 공간의 기준
- 의도한 불확실성과 조작·진행 정보를 놓쳐 생기는 혼란을 구분한다. 모든 출구를 밝히거나 모든 목표를 즉시 보여 주는 규칙을 강제하지 않는다.
- 같은 구역을 다시 지날 때 달라지는 소리·시야·흔적이 무엇인지 살핀다. 변화가 미정이면 새 연출을 확정하지 않는다.
- 프로젝트의 Visual Blockout 방향을 따른다. 재질·임시 에셋·조명으로 공포 공간의 분위기와 시야를 함께 검증한다. 아트를 마지막까지 미루는 절차를 강제하지 않는다.
- 공간 이동과 시야의 리듬만 맡는다. 게임 전체의 세션·복귀 흐름은 `game-loop-planning`이 맡는다.

## 결과
검토 요청에는 문제와 근거, 고칠 후보를 채팅에 보고한다.
기획서 작성 요청에는 `game-planning`의 기존 형식으로 정리한다. 별도 레벨 문서 형식을 의무화하지 않는다.
실제 씬·프리팹·코드·이미지 생성은 설계 요청에 포함된 것으로 보지 않는다.
