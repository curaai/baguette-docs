# Narrative 컨텐츠 작성 스킬 (narrative 전용)

이 스킬은 **`narrative/**`에 들어갈 narrative 문서**(세계관 시트, 용어표 항목, 캐릭터 스냅샷, 로어 단편, 톤 가이드 등)를 쓰기 위한 가이드와 템플릿이다.

## 적용 범위 (반드시 준수)

- **출력 경로:** vault 루트 기준 `narrative/**`만 사용한다. 다른 분야의 문서에는 쓰지 않는다.
- **다루는 내용:** 세계관, 설정, 용어, 캐릭터·존재, 장소, 시대·연표, 로어 단편, 톤·금지어 등 **narrative만**.
- **다루지 않는 내용:** 코어루프, 메카닉, 수식, 시스템 다이어그램, UI 흐름, 데이터 스키마, 코드 델타.
- 메카닉이 narrative와 관련될 때는 “세계 안에서 어떻게 보이는가”의 **프레이밍**까지만 적고, 메카닉 본문은 기획 담당자에게 맡긴다. 문서 연결은 폴더 README의 목차 표에 둔다.

## 언제 쓰나

- `narrative/`에 새 세계관·용어·로어·캐릭터 문서가 필요할 때
- 기존 narrative 초안이 톤·용어가 흩어져 있어 정본 한 장으로 정리해야 할 때
- 메카닉 문서가 “세계 톤”과 어긋나는 표현을 쓰고 있어 narrative 쪽 정본이 필요할 때
- 선택·분기·환경 서사의 의미와 전달 방식을 설계하거나 검토할 때

## 출력 규칙

- 본문은 **세계 안에서 읽히는 글**(서술·앵커·톤)로 쓴다. 표/명세형 문체는 최소화.
- 새로운 용어는 **용어표 항목**으로 따로 박는다(중복 방지).
- 톤·금지어는 **명확한 예시 1개 이상**과 함께 둔다.
- narrative 외 주제(메카닉·UI·수치)는 본문에 넣지 않는다. 필요한 별도 작업은 채팅에서 짚고, 내부 문서 링크는 폴더 README에 둔다.

## 작업 절차

`narrative/README.md`에서 관련 문서를 찾아 톤·용어 충돌을 확인한다.
선택·분기·플레이를 통한 이야기 전달이 대상이면 같은 스킬 폴더의 `references/interactive-story.md`를 함께 읽는다. 용어 정리나 일반 문구 수정에는 불러오지 않는다.
검토만 요청받았으면 관련 자료로 확인한 내용과 수정 후보를 채팅에 보고한다. 파일 작성·용어표 갱신은 실행하지 않는다.
아래 절차는 문서 작성·수정 요청에 적용한다.

1. 같은 스킬 폴더의 `template.md`로 초안을 작성한다. 필요한 선택은 공통 규칙에 맞는 질문 도구로 확인하고 승인된 내용을 파일에 반영한다.
2. 새 용어가 생기면 **용어표 항목**을 같이 추가하거나, 기존 용어표에 1줄 반영.
3. 마지막에 “열린 질문(결정 필요)”과 “충돌·확인 필요”를 정리한다.

## 위임·연동

- 메인 위임 대상: **narrative-director** — 설정·용어·캐논 정리.
- 후속: **writer**(나나) — 위 정본을 기반으로 대사·플레이어 향 카피.
- 메카닉 충돌이 보이면 **game-designer**(마나) 와 정렬한다(메카닉 쪽 정본은 `planning/`).

## 템플릿

- 스켈레톤: 같은 스킬 폴더의 `template.md`
