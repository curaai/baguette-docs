# AI 씬·프랍 제작 파이프라인

## 목적

Tripo3D 등 생성형 도구를 이용해 게임 배경 프랍을 만들되, 반복 생성에 크레딧을 소모하지 않고 프로젝트의 아트 톤과 씬 품질을 유지한다. 프랍 수가 많아도 모든 오브젝트를 같은 제작 절차로 처리하지 않는다.

핵심 원칙은 **소수의 승인된 기반 에셋을 만들고, 변형·조합·배치 규칙으로 씬의 밀도와 다양성을 확보하는 것**이다. AI는 기반 형태와 탐색을 돕고, 씬의 시선 유도·스토리 전달·최종 공포 연출은 사람이 결정한다.

## 제작 흐름

```text
프로젝트 아트 방향 고정
        ↓
프랍 목록 → 패밀리 분류 → 중요도 등급
        ↓
2D 콘셉트 승인
        ↓
멀티뷰 승인
        ↓
Geometry 승인
        ↓
Texture 승인
        ↓
자동 후처리 → 엔진 임포트
        ↓
재질·데칼 변형 → 클러스터·배치 → 조명·연출 검수
```

각 검수 단계에서 승인 전에는 다음 단계의 비용이 드는 생성을 시작하지 않는다. 형태가 승인되고 재질만 문제라면 Geometry를 다시 생성하지 않고 Texture만 수정한다. 반대로 형태가 문제라면 Texture 작업을 진행하지 않는다.

## 아트 방향과 입력 이미지

프랍별 프롬프트를 매번 새로 만들지 않고, 프로젝트 공통의 스타일 기준과 레퍼런스를 고정한다. 기준은 이 프로젝트의 기존 아트 방향에 맞춰 작성한다. 특정 예시의 병원·차가운 팔레트 같은 설정을 그대로 복사하지 않는다.

3D 생성용 이미지는 공포 분위기보다 물체 형태를 명확히 보여주는 데 집중한다.

- 물체 전체가 보이고 가림이 적은 단독 참조 이미지를 사용한다.
- 중립적인 배경과 조명을 쓰고, 과장된 원근·강한 그림자·안개·시네마틱 조명을 피한다.
- 기본 재질과 형태를 생성한 다음, 오염·혈흔·누수·먼지·조명 등 공포 연출을 엔진에서 더한다.
- 멀티뷰는 전면·측면·후면의 비례와 실루엣을 확인하고 3D 생성에 넘긴다.

## 크레딧을 보호하는 생성 게이트

생성 이력을 에셋별 메타데이터로 남긴다. 가능한 경우 모델 버전, Geometry seed, Texture seed, 면 수 제한, 텍스처 옵션, 입력 참조, 승인 상태를 함께 기록한다. Seed와 버전 기록은 결과 재현과 비교를 돕는다.

```yaml
id: temple_lantern_stone_01
family: stone_lantern
references:
  concept: refs/temple_lantern_stone_01.png
  multiview: refs/temple_lantern_stone_01/
generation:
  tool: tripo
  model_version: ""
  model_seed: null
  texture_seed: null
status:
  concept: approved
  multiview: review
  geometry: pending
  texture: pending
```

이 메타데이터는 관리 예시이며 실제 도구가 제공하는 옵션만 채운다. `concept`가 승인되기 전에는 멀티뷰·3D 생성, 멀티뷰가 승인되기 전에는 3D 생성, Geometry가 승인되기 전에는 Texture 생성을 진행하지 않는 것을 기본 규칙으로 한다.

## 프랍 단위가 아닌 패밀리 단위로 만든다

씬의 오브젝트를 전부 별도 AI 에셋으로 만들지 않는다. 형태와 용도가 유사한 프랍을 패밀리로 묶고, 패밀리마다 필요한 수만큼 기반 에셋(Master)을 제작한다. 예를 들어 사찰 환경에서는 목재 문·창호, 석등·석물, 항아리·바구니, 제기·작은 생활 소품처럼 분류할 수 있다.

대략적인 출발점으로, 프랍 100개를 100회 생성하는 대신 15~20개 패밀리로 묶고 패밀리별 1~3개 Master를 만드는 방식을 검토한다. 실제 수는 반복 배치 빈도와 화면상 중요도에 따라 조정한다.

## 중요도에 따라 품질 절차를 나눈다

| 등급 | 기준 | 제작·검수 방식 |
|---|---|---|
| A — Hero | 가까이 보거나 상호작용하고, 단서·스토리에 직접 관여 | 콘셉트부터 후처리까지 전체 절차. 실루엣·표면·상태를 개별 검수 |
| B — 반복 기반 | 씬 여러 곳에 반복 배치되어 공간의 구조를 만드는 프랍 | 패밀리 Master를 승인하고 재질·형태 변형으로 파생 |
| C — Dressing | 작고 주변적인 장식·잔해·잡동사니 | Prop Pack으로 묶어 생성·검수하고 Asset Pool에 등록 |

플레이어가 가까이 접근하거나, 상호작용하거나, 빛을 비추거나, 내용을 읽는 에셋은 A 등급으로 올린다. 멀리 있거나 실루엣만 읽히는 프랍은 낮은 등급으로 처리한다. 비율은 프로젝트의 시작 가이드일 뿐 고정 할당량이 아니다.

## 기반 에셋을 변형해 다양성을 만든다

각각 별도 모델로 생성하던 낡은 의자·쓰러진 의자·먼지 쌓인 의자는 기반 에셋과 상태 변형으로 분리한다.

```text
Base Asset
+ 위치·회전·크기
+ 파손/열림 등 필요한 Geometry 변형
+ Material Instance 또는 Vertex Paint
+ Decal (먼지·물때·혈흔·표식 등)
= 파생 배치
```

변형은 무작위로 많이 만드는 것보다 아트 방향에 맞는 통제된 범위를 정한다. 오염을 AI 메시마다 다르게 구워 넣으면 에셋마다 표면 표현이 달라져 씬의 톤이 깨질 수 있으므로, 반복되는 때·풍화·자국은 공통 재질과 데칼 체계로 관리한다.

## 모듈형 키트와 Prop Pack

분리 조합이 이득인 구조물은 완성품 하나 대신 재조합 가능한 키트로 만든다. 예를 들어 선반은 프레임·선반판·문·서랍·손잡이로 나눌 수 있다. 단, 모든 프랍을 억지로 모듈화하지 않고 변형 효과가 큰 패밀리에 한정한다.

작은 소품은 낱개 승인 대신 용도와 공간을 공유하는 Prop Pack으로 관리한다. 예: `temple_storage_clutter`에 작은 항아리, 깨진 그릇, 천 조각, 나무 상자 등을 묶는다. 검수 기준은 각 변형의 완벽함보다 씬에 배치했을 때 품질과 톤이 일관적인지에 둔다.

## 씬 배치: 에셋, 클러스터, 규칙

씬에서 에셋 하나씩 직접 배치하는 작업을 줄이기 위해 배치 풀과 클러스터를 만든다.

- 풀은 배치 맥락을 담는다. 예: 벽면 소품, 바닥 잔해, 제단 주변, 창고 적치물.
- 클러스터는 함께 놓여야 자연스러운 소품 묶음이다. 예: 상자 + 천 조각 + 깨진 그릇.
- 각 클러스터는 회전·크기·구성 일부 제거·재질/데칼 변형을 허용한다.
- 자동 배치는 벽·모서리·동선·시야 같은 규칙에 따르게 하고, 주요 동선과 스토리 프랍의 위치는 수동으로 확정한다.

AI가 좌표를 직접 정하도록 하기보다 배치 레시피(공간의 초점, 구역별 프랍 풀, 밀도, 동선 유지 규칙)를 제안하게 하고 실제 배치는 엔진의 배치 규칙이나 에디터 도구가 수행하도록 한다. 무작위 배치 후에는 반복 패턴과 가림, 플레이 동선, 공포 연출의 초점을 사람이 검수한다.

## Greybox 대신 Visual Blockout

공포 씬은 실루엣·재질·그림자·표면 정보가 분위기에 크게 관여하므로 회색 박스만으로 품질을 판단하기 어렵다. 공간 검증 초기부터 최종에 가까운 벽·바닥 재질과 조명을 두고, 큰 구조물은 검수 가능한 임시 에셋, 중요 프랍은 초기 승인본, 잡동사니는 간단한 풀로 채운 Visual Blockout을 사용한다.

초기 단계에서는 최종 토폴로지보다 화면에서 공간의 분위기와 시야가 목표에 가깝게 읽히는지를 우선 검수한다. 스토리 프랍 위치, 플레이어 시선, 조명·안개·후처리의 최종 연출은 자동 생성에 맡기지 않는다.

## 프로그래머의 자동화 범위

에셋 Manifest, 승인 상태, 후처리와 검증 절차를 스크립트로 반복 가능하게 만든다. 생성·후처리·엔진 임포트는 독립 단계로 두어 실패 원인을 구분한다.

```text
manifest/       에셋 ID·패밀리·참조·seed·상태
concept/        승인된 2D 콘셉트
multiview/      승인된 각도별 참조
raw/            생성 원본
processed/      정리·변환된 메시
textures/       텍스처 맵
scripts/        검증·후처리·임포트 도구
```

자동 검증은 파일 존재·형식, 크기/축척 범위, 면 수 등 반복 가능한 기준을 확인한다. 시각 품질과 세계관 적합성은 사람의 승인 게이트로 남긴다.

## 이 프로젝트에 적용할 때

사찰 환경의 스타일 기준은 기존 프로젝트 아트 방향을 따른다. 병원 배경, 혈흔, 의료 장비 등의 예시는 일반적인 파이프라인을 설명하기 위한 사례이므로 이 프로젝트의 콘텐츠로 간주하지 않는다. 사찰별 프랍 목록과 패밀리, Hero 프랍, 클러스터 구성은 각 공간의 설정과 씬 목적에 맞춰 정한다.
